# AGENTS.md

Example project showing how to publish an npm package to Repsy NPM (repo.repsy.io) from GitHub Actions. It has no source code:
just `package.json` and one workflow. Related: `../repsy-docs` (user docs), `../repsy-cli`.

## Layout

- `package.json`: scoped package `@foo/repsy-npm-publish-pipeline`, version `1.1.0`; the only script is a placeholder `test` that fails. `package-lock.json` is generated by npm, do not hand-edit.
- `.github/workflows/cd.yml`: the publish workflow; it sets `permissions: contents: read`.
- `.github/dependabot.yml`: Dependabot config.
- `README.md`: title plus one description line.

## Commands

- No build or test. `npm install` is what CI runs. `npm publish` needs a Repsy deploy token and publishes a real package; do not run it locally.

## CI and release

`.github/workflows/cd.yml` ("Repsy NPM") runs on push to `main` and manual dispatch, on the `repsy-sm` runner: checkout, Node 24,
`npm install`, fails unless the package name is scoped (`@scope/name`), writes `~/.npmrc` for `https://repo.repsy.io/npm/<REPSY_USERNAME>/<REPSY_REPO>`
from the secrets `REPSY_USERNAME`, `REPSY_DEPLOY_TOKEN`, `REPSY_REPO`, then `npm publish`. Every push to `main` publishes, so bump the
`version` in `package.json` for a new release (npm rejects a repeated version).

## Conventions

- Recent commit titles: `RPS-2342: Use repsy-* runners in workflows (#3)` (squash merges add ` (#N)`); older history is `updated` and merge commits. Ticket branches look like `rps-2342-use-repsy-runners`.
- The checkout may sit on a feature branch; check `git branch --show-current` and use a worktree for new work.
- Never put tokens in the workflow or `.npmrc` in the repo; secrets come from GitHub secrets.
